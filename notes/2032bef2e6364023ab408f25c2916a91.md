粒子的内容居然不是单独某个粒子算的，数组中某个为位置的粒子会保持一个相同的restart_phase，
`	double system_phase = time / lifetime;`

```cpp
		if (randomness_ratio > 0.0) {
			uint32_t _seed = cycle;
			if (restart_phase >= system_phase) {
				_seed -= uint32_t(1);
			}
			_seed *= uint32_t(pcount);
			_seed += uint32_t(i);
			double random = double(idhash(_seed) % uint32_t(65536)) / 65536.0;
			restart_phase += randomness_ratio * random * 1.0 / double(pcount);
		}

		restart_phase *= (1.0 - explosiveness_ratio);
		double restart_time = restart_phase * lifetime;
		bool restart = false;

```

这个随机数以cycle为seed，当restart_phase > system_phase 的时候，说明上一轮的这个粒子生命周期还没结束，通过直接对cycle进行-=1来恢复成上以轮的数据，这个设计还挺巧妙的，相当于其实是把粒子效果做成一个环，randomness_ratio是这个随机数的效果，虽然说是随机数，但是其实还是确定的

也就是粒子效果通过这种"确定随机"复用资源，来实现了复用。第 i 个粒子。当然，不开随机的时候相当于直接就是使用的某个粒子


```cpp
		restart_phase *= (1.0 - explosiveness_ratio);
		double restart_time = restart_phase * lifetime;
		bool restart = false;
```

某个位置的粒子的生命周期永远都是对应的某一段，而不是走完全量，小段的平移给人连续运动的感觉，而这些位移可以连接在一起全靠随机系统本身的确定性。非随机的随机，restart_time自然就是这个区间的粒子"应该"重置的时间


```cpp
if (time > prev_time) {
			// restart_time >= prev_time is used so particles emit in the first frame they are processed

			if (restart_time >= prev_time && restart_time < time) {
```

对事件进行计算，判断要不要复位。三个分支

这里的prev_time 来自初始化的时候

```cpp
	double prev_time = time;
	time += p_delta;
```

而 time在这之后进行了cycle的判断取余，当time > prev_time 说明取余后time仍然要大
第一个重置分支，发射器的生命周期没有重置，但是到了粒子自己的重置时间`if (restart_time >= prev_time && restart_time < time) `  拿就标记重置。
`	local_delta = time - restart_time;` 则是一个时间补全算法，会计算粒子诞生到现在差了多少，开关这个开关会影响粒子的发射是"这一帧" 还是会补全中间的时间。另外两个差不多不多讲了

第二个分支是 当cycle发生了变化，也就是发射器已经重置了，的时候，local_delta > 0 （local_delta来自传入的p_delta*speed_scale ） 然后根据时间去标记restart

```cpp
if (restart_time >= prev_time) {
				restart = true;
				if (fractional_delta) {

			} else if (restart_time < time) {

					local_delta = time - restart_time;
				}
			}
```

第三个分支判断粒子本身的生命周期。粒子存活时间大于粒子的生命周期了，就进行重置
